# B站 PCDN 限速修复(浏览器端用户脚本)

> 这是**可选附件**。用不用取决于你在校园网下看 B站 会不会卡。
> 和校园网自动认证是两件独立的事,不影响主脚本。

---

## 问题现象

B站 网页能打开、视频列表正常、封面正常,但**视频一直转圈、缓冲不动**。

## 根因(实测)

在校园网(运营商代拨出口)下,B站 `/x/player/playurl` 接口**优先返回 PCDN 流地址**:

```
baseUrl   = xy........mcdn.bilivideo.cn     ← 播放器默认用这个
backupUrl = [ ........edge.mountaintoys.cn,  ← 也是 PCDN
              cn-xxxx-cm-01-01.bilivideo.com ]  ← 正规 CDN(快)
```

而这个 PCDN 常被限速到不可用的程度。实测对比:

| 地址类型 | 实测速度 | 1080p(需 6 Mbps) |
|---|---|---|
| PCDN(`mcdn.bilivideo.cn` / `mountaintoys.cn`) | 2.1 Mbps(8MB 要 21 秒;大文件直接超时) | ❌ 不够,必然卡 |
| 正规 CDN(`cn-*.bilivideo.com`) | 147 ~ 157 Mbps | ✅ 绰绰有余 |

**关键点**:快地址 B站 自己就在 `backupUrl` 里给了,只是播放器默认优先用 `baseUrl`(PCDN),不会主动切。

## 修复方案(v2:按实测速度选节点)

给该流的每个候选地址**实测速度**,把最快的提为 `baseUrl`:

1. 收集该流的全部候选地址(`baseUrl` + `backupUrl`)
2. 对候选主机发 64KB `Range` 请求实测速度
3. 按实测速度排序,最快的当主地址,其余降为备份
4. 结果写入 `localStorage`(6 小时有效),越用越准、刷新页面不丢

排序规则:**实测最快(降序)→ 没测过(非 PCDN 优先)→ 实测失败**

> 为什么不"一律把 PCDN 换掉":因为那个假设是错的 —— 实测中 PCDN 有时 36.9 Mbps,
> 而正规备份只有 16.1 Mbps,盲选反而更慢。所以必须按速度选,而不是按类型选。

同步/异步的取舍:

| 路径 | 行为 |
|---|---|
| `fetch` | 可以 await 测速,**首次播放就能选对**。只在遇到没测过的主机时才等,最多 1.2 秒;缓存热了零延迟 |
| `XHR` | XHR 响应必须同步交还,没法等。按缓存同步排序,测速丢后台,**下一次请求生效** |

控制台会打印实际走的是 `fetch` 还是 `xhr` 路径。

其它原则:
- 只换主机,**不动路径、不动签名** → 不会失效
- 保留 DASH,**不降画质**(不像 `platform=html5` 会降级成 durl)
- 不依赖 DNS / hosts(注意:**hosts 挡不住它**,PCDN 用随机子域名,hosts 不支持通配符)

## 安装

1. 浏览器安装 **Tampermonkey** 扩展
2. 把 `bilibili-nopcdn.user.js` **拖进浏览器窗口**,Tampermonkey 弹出安装页 → 点「安装」
3. 打开 B站 任意视频,按 `F12` → Console,应能看到:

```
[No-PCDN] v2 已加载（按实测速度选节点）。自检 __noPcdnStats()  清缓存 __noPcdnReset()
[No-PCDN] fetch 路径：替换 9 个主地址（已测速 3 个节点），使用节点: cn-xxxx-cm-01-01.bilivideo.com
```

## 自检与排错

| 命令(在 Console 里执行) | 作用 |
|---|---|
| `__noPcdnStats()` | 看替换次数、走了哪条路径、每个节点当前记录的速度 |
| `__noPcdnReset()` | 清空速度缓存,下次播放重新测速 |

第一次装完缓存是空的,所以**头一两个视频可能还按启发式选节点**;之后每个节点的速度都被记下来,就会直接选最快的。

## 验证

在 `F12` → Network 里过滤 `mcdn`,应**不再出现** `mcdn.bilivideo.cn` 的媒体请求。

## 卸载

Tampermonkey 管理面板里关闭或删除该脚本即可,不改动系统任何设置。

## 离线测试

```powershell
node _test-rewrite.cjs
```

`_test-playurl.json` 是**合成的样本数据**(假主机名、假签名),用来验证排序与改写逻辑,
不含任何真实账号、IP 或签名。想用真实响应测的话,自己抓一份替换即可。
